# Sprint 2 test and coverage report

## Current coverage baseline

The latest full test run reports:

- Line coverage: 97.0% (708 / 730)
- Function coverage: 100.0% (56 / 56)
- Branch coverage: 89.5% (1,146 / 1,281)
- Automated tests: 102 passed, 0 failed

## How the branch metric is calculated

Coverage is generated by GCC instrumentation and gcovr. The report uses
\`--exclude-throw-branches\` and \`--exclude-unreachable-branches\`. These options
remove exception-only arcs and branches attributed to lines without useful
source code, such as compiler-generated dead code. They do not exclude
application source files or manually selected business logic.

The CI job has quality gates of at least 80% line coverage and at least 80%
branch coverage. It also publishes the detailed HTML report as the
\`sprint2-coverage-report\` workflow artifact.

## Running locally

From \`Sprint2/\`, after compiling and running the coverage-instrumented test
executable in \`test-runtime/\`, run:

\`\`\`bash
gcovr --root . --filter 'src/.*' \\
  --exclude-throw-branches --exclude-unreachable-branches \\
  --html-details coverage.html --print-summary \\
  --fail-under-line 80 --fail-under-branch 80
\`\`\`

This is an academic prototype. Coverage is a test-quality signal, not proof
that the program is free of defects. Interactive and platform-specific
scenarios may still require manual verification.
